Use for: Explain an API, idempotency, synchronous versus asynchronous processing, reconciliation, technical risks, and how you would test a system.
Define → Mechanism → Application → Risks / Trade-offs → Verification. Know each concept at four levels: meaning, when to use it, what may go wrong, and how to test it.

Critical banking distinctions
Distinction
Why it matters
Payment submitted ≠ payment settled
Submission may only mean an instruction was accepted.
API timeout ≠ transaction failure
The downstream operation may have succeeded even if the response was lost.
Ledger balance ≠ available balance
Holds, reservations and account rules can affect spendable funds.
Analytics data ≠ authoritative financial data
Product events monitor behavior, but ledger/reconciliation records govern financial correctness.
Successful retry ≠ safe retry
Repeated requests must not trigger multiple financial operations.

Build vs. buy
Build
Buy / integrate
Greater architectural control
Faster access to mature capability
More direct customization
Vendor and roadmap dependence

Integration, contract and resilience concerns
Speed vs. correctness
In financial products, a fast but misleading confirmation can be worse than a slower but truthful acknowledgment. Optimize perceived responsiveness separately from actual financial finality. Confirm receipt of an instruction without pretending it is settled.
